# AI Knowledge Hub

**AI Knowledge Hub** — внутрішній каталог AI-знань Metinvest Digital: єдина
точка входу до навичок (skill-пакетів та інструкцій), промптів, інструкцій,
кейсів, агентів, MCP-серверів і корисних посилань компанії.

Хаб **не має вбудованого чату з ШІ й нічого не виконує**. Він зберігає,
впорядковує й віддає матеріали: промпт копіюють, інструкцію читають, пакет
навички завантажують і використовують у власному інструменті (Claude,
ChatGPT, корпоративний агент, локальне середовище).

Репозиторій містить веб-застосунок: REST API на Flask і SPA без збірки, яку
віддає той самий Flask.

## Можливості

- 🔐 **Вхід** за логіном і паролем або через корпоративний акаунт Entra ID;
  ролі призначає адміністратор вручну, корпоративний вхід їх не змінює
- 👥 **Ролі за розділами** — адміністратор, менеджер розділу (модерує лише
  призначені розділи, один чи кілька) і користувач; ознаки «Експерт» і
  «Відповідальний за ідеї» в профілі (див. [«Ролі та публікація»](#ролі-та-публікація))
- 📚 **«Матеріали»** — виділений пункт бічної панелі над розділами: увесь
  каталог із фільтрами за видом і атрибутами (на телефоні — окрема вкладка)
- 🗂️ **Каталог** у фірмовому стилі Metinvest Digital: **навички**, **промпти**
  (копіювання в один клік), **інструкції** та **кейси** (оформлений текст),
  **агенти**, **MCP-сервери** та **корисні посилання**; фільтри за видом і
  атрибутами, пошук, «Обране» для будь-якого елемента. Колір картки завжди
  відповідає виду матеріалу; на плитці — до трьох тегів, клік по тегу
  показує всі матеріали з ним
- 🧩 **Навички — хостинг, а не запуск.** Навичка — це пакет (`.zip`/`.skill`
  зі `skill.md`, кодом і файлами) або інструкція без пакета. Картка показує
  опис, вхідні дані й результат, стартовий промпт, інструкцію з `skill.md` і
  перелік файлів пакета; пакет опублікованої навички може завантажити будь-хто,
  а подати свою навичку на розгляд — кожен користувач.
  **Лічильник завантажень** — популярність навички в каталозі
- 🔌 **MCP-сервери** — endpoint копіюється одним кліком у конфіг клієнта;
  внутрішні сервери позначені окремо від публічних
- 🧭 **Розділи й колекції** — дзеркалять розділи корпоративного хабу; розділ із
  посиланням веде до зовнішнього порталу, розділ без посилання показує власні
  матеріали
- ➕ **Додає кожен, публікує менеджер розділу**: майстер (вид → зміст → опис)
  приймає текст або файл (`.txt/.md/.docx/.pdf` — текст витягується у поле,
  оригінал прикріплюється до картки) і завершується двома кнопками: «Зберегти
  чернетку» й «Подати на розгляд» (для того, хто модерує обраний розділ, —
  «Опублікувати»). Якщо в каталозі вже є матеріал із тією самою назвою,
  майстер попереджає про можливий дубль. **Попередня модерація**: матеріал
  з'являється в каталозі після схвалення менеджером розділу
- ✍️ **Візуальний редактор тексту** (`app/static/editor.js`) у майстрі, повному
  редакторі менеджера й інструкції навички: панель оформлення (заголовки,
  жирний, курсив, код, списки, цитата, посилання, таблиця, зображення),
  вставка з Word і Google Docs з очищенням стилів, вкладка «Markdown».

  змінюються; у промптах `<теги>` лишаються текстом. Імпорт `.docx`

  картинки. **Зображення в тексті** вставляються кнопкою, знімком екрана з

- 🔎 **Пошук мовою задачі** з синонімами та **помічник** «Опишіть задачу»: він

## Ролі та публікація

Ролі призначає адміністратор вручну в «Керування → Користувачі» (фідбек
тестування, п. 11); корпоративний вхід Entra ID їх не змінює, новий
співробітник отримує роль «Користувач». Правила — в `app/core/access.py`.

| Роль | Що може |
| --- | --- |
| **Користувач** | Переглядає каталог і користується контентом, коментує, оцінює, додає в «Обране», подає ідеї. **Створює власний контент усіх видів**, включно з навичками, і **подає його на розгляд**; керує своїм: редагує, забирає з розгляду, знімає з публікації, видаляє |
| **Менеджер розділу** | Модерує матеріали й навички **призначених розділів** (одного чи кількох): схвалює або повертає подане з причиною, редагує, архівує, знімає з публікації, видаляє, видаляє коментарі; у своїх розділах публікує одразу; бачить аналітику й KPI. Заступник — та сама роль у тих самих розділах |
| **Адміністратор** | Усе: модерація будь-якого розділу (зокрема матеріалів без розділу), структура каталогу, довідники, маршрути, налаштування, користувачі й ролі |

Ознаки в профілі ставить адміністратор: **«Експерт»** (позначка біля автора на
матеріалах) і **«Відповідальний за ідеї»** (розділ «Ідеї» в «Керуванні»).

**Попередня модерація** (фідбек тестування, п. 12; `app/services/moderation_service.py`):

1. Автор зберігає чернетку (її бачать лише він і менеджери розділу) або
   подає матеріал на розгляд. Без розділу подати не можна — нікому було б
   розглянути. Хто модерує обраний розділ, публікує одразу.
2. Менеджери розділу (якщо їх немає — адміністратори) отримують сповіщення.
   Матеріал з'являється в черзі «На розгляді» на сторінці «Керування →
   Модерація»; скільки рішень чекає, видно на перемикачі «Керування».
3. Менеджер схвалює — матеріал з'являється в каталозі, власником стає автор.
   Або повертає на доопрацювання з причиною — автор бачить її в картці,
   виправляє й подає знову.
4. Зміни автора до опублікованого **не ховають його**: вони стають
   «пропозицією змін» (`pending_data`) і замінюють опубліковану версію після
   схвалення. Менеджер бачить, що було й що стане, і схвалює чи відхиляє;
   автор може забрати свої зміни. Так само з атрибутами й новою версією пакета
   навички. Файли, додані до опублікованого, з'являються одразу — менеджер
   розділу отримує про них сповіщення.

Менеджер не може перенести матеріал у розділ, якого не модерує.

## Швидкий старт

### 1. Передумови
- Python **3.11+**
- `pip` та `venv`

### 2. Клонування та віртуальне середовище

```bash
git clone <repo-url>
cd smart-digital-skills

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

### 3. Встановлення залежностей

```bash
pip install -r requirements.txt
```

### 4. Налаштування середовища

```bash
cp .env.example .env
```

За потреби відредагуйте `.env` (секрети, початковий пароль адміна). Для
локального запуску значень за замовчуванням достатньо.

### 5. Ініціалізація бази та початкові дані

```bash
python -m scripts.init_db    # версійні міграції (Alembic) + довідники
python -m scripts.seed       # демо-дані: ролі, користувачі, каталог, навички
```

> **Оновлення наявної бази.** Після `git pull` виконайте
> `python -m scripts.init_db` (або `alembic upgrade head`). Видаляти
> `instance/profihub.db` не потрібно. Довідники синхронізуються при старті
> автоматично — це дані, а не схема.

### 6. Запуск

```bash
python wsgi.py
```

Відкрийте **http://localhost:5000** у браузері.

> Production-запуск: `bash startup.sh` — застосовує міграції й піднімає
> gunicorn з параметрами, придатними для SQLite. Розгортання на Azure App
> Service — у [`DEPLOY-AZURE.md`](DEPLOY-AZURE.md).

> **Резервна копія бази:** `python -m scripts.backup_db`. Скрипт користується
> онлайн-бекапом SQLite, тож копію можна знімати на працюючому застосунку —
> на відміну від `cp`, який під навантаженням дає пошкоджений файл.

## Оновлення з версії з чатом

Міграція `b7e2d4f6a8c1` (`catalog_only`) прибирає з бази все, що стосувалося
чату й запуску навичок. **Вона руйнівна:** дані видалених таблиць не
повертаються навіть `alembic downgrade` — він відновлює лише структуру.
**Перед оновленням зробіть копію:** `python -m scripts.backup_db`.

Що видаляється:

- сесії й повідомлення чату, облік токенів, квоти та ліміти;
- реєстр моделей і доступи до моделей;
- групи, членство, запрошення та призначення навичок групам;
- особисті встановлення навичок, параметри запуску навичок, журнал аудиту;
- колонки навичок, потрібні лише для запуску (модель, runtime, entrypoint,
  лічильник активацій). Натомість з'являється лічильник завантажень.

Наступна міграція `c4f1a9e3d2b7` створює таблицю сповіщень, якої бракувало в
базовій міграції. Без неї на чистій базі (зокрема на Azure) не працювали
сповіщення в застосунку.

Міграція `a8d0c2e4f6b9` додає `users.tour_completed_at` — коли людина
пройшла знайомство з інтерфейсом. Порожнє поле в усіх, тож знайомство
побачать і нові, і наявні користувачі (інтерфейс для них теж новий);
пропустити його можна одним кліком.

Міграція `f6b8d0e2a4c7` заповнює власника в уже опублікованих матеріалах і
навичках без нього: хто опублікував за журналом, інакше хто створив, інакше
автор.

Міграція `e5a7c9d1f3b6` переводила каталог на пост-модерацію: матеріали, що
чекали розгляду, публікувалися; відгуки, залишені раніше, лишаються
приватними й у публічних коментарях не з'являються.

Міграція `e7a9c1d3f5b8` повертає попередню модерацію й вводить ролі за
розділами: роль `skill_manager` стає `section_manager` («Менеджер розділу»), і
кожен колишній менеджер каталогу отримує **всі наявні розділи** — у день
оновлення ніхто не втрачає доступ, а зайві розділи адміністратор прибирає в
«Користувачах». Додаються таблиця `section_managers`, ознаки
`users.is_expert` і `users.is_ideas_owner`, статус «На розгляді» та поля
пропозиції змін у матеріалів і навичок. Опубліковане лишається опублікованим.

Вкладення до карток каталогу зберігаються. Особисті файли з колишнього
розділу «Мої файли» і файли, створені запуском навичок, міграція не чіпає,
але в інтерфейсі їх більше не видно. Це записи `user_files` з порожнім
`resource_id` і відповідні файли в `instance/user_files/<GUID>/`. Їх можна
вивантажити користувачам або видалити вручну.

Створюються скриптом `seed`:

| Роль | Логін | Пароль |
| --- | --- | --- |
| Адміністратор | `admin` | `Admin123!` |
| Менеджер розділів Toolbox і Insight Center | `skillmanager` | `Skill123!` |

| Користувач | `user2` | `User123!` |

> Пароль адміна можна змінити через `ADMIN_USERNAME` / `ADMIN_PASSWORD` у `.env`
> **перед** запуском `seed`.

### Що подивитися після входу
- **user1 / user2** — «База знань»: «Матеріали» з фільтрами, пошук, «Обране», коментарі;
  навичка **Word Counter** — завантаження пакета й перелік його файлів;
  **Summarizer** — навичка-інструкція без пакета; «Наповнення каталогу» →
  «Додати матеріал» — подати свій матеріал чи навичку на розгляд.
- **skillmanager** — дзвіночок і «Керування → Модерація»: черга «На
  розгляді» (подання й зміни до опублікованого), усі матеріали своїх
  розділів, коментарі й оцінки; аналітика й KPI.
- **admin** — модерація всіх розділів, структура каталогу, ідеї, маршрути,
  категорії навичок і керування користувачами (ролі, розділи, ознаки).

## Навички в каталозі

Навичка буває двох видів:

- **Пакет** — архів `.zip`/`.skill` зі `skill.md` і будь-якими файлами.
  Користувач бачить опис, інструкцію з тіла `skill.md` і перелік файлів, а
  кнопкою «Завантажити» отримує архів.
- **Інструкція** — навичка без пакета: текст інструкції та стартовий промпт,
  які копіюють у свій інструмент. Інструкцію редагують у редакторі навички.

### Керування

1. **Створення — завантаженням пакета**, будь-ким: у майстрі «Додати
   матеріал» → «Навичка». Атрибути (назва, версія, автор, опис, категорія)
   читаються з фронтматеру `skill.md` і редагуються потім у редакторі
   навички — з її картки або з «Керування → Модерація». Розділ обирають у
   майстрі: його менеджер розгляне навичку.
2. **Статуси**: опублікована (`published`) — її бачать і завантажують усі;
   на розгляді (`review`) і чернетка (`draft`) — бачать лише автор і менеджери
   розділу. Автор керує своєю навичкою, менеджер розділу — навичками своїх
   розділів (за правилами попередньої модерації).
3. **Нова версія** — завантаження пакета в картці наявної навички. Лічильник
   завантажень, коментарі, іконка й місце в каталозі зберігаються, інструкція
   оновлюється з нового `skill.md`. Нова версія опублікованої навички від
   автора чекає схвалення: до того завантажують попередню, а менеджер може
   переглянути нову (`/download?pending=1`).
4. **Видалення** прибирає пакет, іконку, позначки «Обране»; коментарі
   лишаються без прив'язки до навички.

### Структура пакета

```
my-skill.zip
├── skill.md            # YAML-фронтматер + інструкція (Markdown)
├── main.py             # будь-які файли…
└── lib/                # …і вкладені папки
    └── counter.py
```

```markdown
---
name: Word Counter
description: Підраховує слова, символи та рядки в тексті.
author: Metinvest Digital
category: Текст
version: 1.0.0
---
# Інструкція: як користуватися навичкою
```

Архів може мати одну верхню теку (`my-skill/skill.md`, …) або файли в корені.
Готовий приклад — [`examples/skills/word-counter/`](examples/skills/word-counter);
`seed` пакує його й реєструє як навичку **Word Counter**.

### Безпека

Сервер пакети **не розпаковує на диск і не виконує**. При завантаженні архів
перевіряється на шляхи з `..`, абсолютні шляхи та розмір у розпакованому
вигляді (`SKILL_PACKAGE_MAX_UNZIPPED`, захист від zip-бомб): розпаковувати його
буде вже користувач, і небезпечний архів не має потрапити в каталог.
Подавати пакети на розгляд може кожен користувач; менеджер розділу схвалює
навичку, повертає її з причиною, знімає з публікації чи видаляє.

## Вкладення до карток

До картки матеріалу можна прикріпити файли (оригінал документа, шаблон,
приклад). Файл видимий рівно тим, хто бачить саму картку, і віддається лише
з JWT-токеном — інтерфейс завантажує його через `fetch`, а не звичайним
посиланням. Додає вкладення автор картки або менеджер. Файли лежать у
`instance/user_files/<GUID>/` (теку можна змінити через `USER_FILES_DIR`),
ліміт розміру — `USER_FILE_MAX_BYTES`.

**Зображення й відео** показуються прямо в картці, одразу під описом:
мініатюри (клік — перегляд на весь екран зі стрілками) і вбудований плеєр
з перемотуванням. Теги `<img>` і `<video>` не вміють передати JWT, тож
список вкладень видає для них **підписане посилання** на 6 годин,
прив'язане до файлу й користувача; права на картку перевіряються при кожному
запиті. Перегляд мають растрові зображення (`png`, `jpg`, `gif`, `webp`,
`avif`, `bmp`) і відео (`mp4`, `webm`, `ogv`, `mov`). SVG — ні: це документ
зі скриптами, який, відкритий напряму, виконав би їх від імені користувача.

**Зображення в тексті матеріалу** — теж файли картки, з позначкою `inline`
(у списку вкладень їх не показують). Редактор завантажує картинку через
`POST /catalog/images` і пише в Markdown постійне посилання
`/api/catalog/files/<id>/preview`; інтерфейс показує його через підписане
посилання зі списку файлів картки. Поки матеріал не збережено, картинка ні до
чого не прив'язана й видна лише тому, хто її вставив; під час збереження
тексту вона прив'язується до картки, а прибрані з тексту картинки
видаляються разом із файлами. Картинки з покинутого майстра прибираються
через дві доби. Тип визначається за вмістом файлу (PNG, JPEG, GIF, WebP,
AVIF), ліміт — `INLINE_IMAGE_MAX_BYTES` (10 МБ); картинки з `.docx`
потрапляють у текст тим самим шляхом.

## Тестування

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Покрито ролі й права за розділами, видимість чернеток, попередню модерацію
(`tests/test_moderation.py`: подання, схвалення, повернення з причиною,
пропозиції змін, сповіщення менеджерам розділу), коментарі й оцінки, хостинг
навичок (видимість, завантаження й
лічильник, перелік файлів, нова версія, видалення), вкладення, пошук і
помічника, ідеї, маршрути, KPI, Entra ID, повноту видалення користувача.
`tests/test_migrations.py` проганяє міграції на чистій базі, звіряє схему з
моделями, перевіряє відкат і перетворення даних.

`tests/e2e/` — браузерні перевірки сценаріїв, логіка яких живе у фронтенді:
фільтр видів в «Обраному», кнопки «Зберегти чернетку» й «Подати на розгляд» в
майстрі, цикл модерації (подання, черга менеджера, схвалення змін) і
призначення розділів менеджеру, попередження про матеріал із тією самою назвою, порядок блоків
«рівень → наступний крок → маршрути» на сторінці «Для вас», підказка «Як
увійти» на сторінці входу. Застосунок піднімається на тимчасовій базі й
відкривається в Chromium через Playwright. Браузер, якщо його ще немає:
`python -m playwright install chromium`. Без Playwright ці тести
пропускаються.
